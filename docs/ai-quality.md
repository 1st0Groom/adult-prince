# NPC 대화 품질 우선 개발

2026-11-03 사용자 결정: 화면보다 AI 품질을 먼저 검증한다. 대표 결함은 건강정보를 캐묻는 행동과 존재하지 않는 기억이다.

## 현재 구현
NPC 대화 전용 프롬프트, NPC별 가시성·민감정보 표시 필터, 근거 ID와 선택지 ID 검증, 로컬 OpenAI 호환 chat/completions 서버 연결기, 고정 평가 사례 10개. 게임 상태를 변경하는 출력 키는 거절한다. 네트워크 연결 테스트는 모의 응답으로 검증했다.

## 실행
Node.js 22 이상에서 npm test. npm run eval:prepare는 모델 호출 없이 평가 입력을 조립한다. 로컬 모델 서버를 실행한 뒤 LOCAL_AI_BASE_URL에 /v1까지의 주소, LOCAL_AI_MODEL에 서버가 제공하는 정확한 모델 ID를 설정하고 npm run eval:dialogue를 실행한다. 자동으로 모델을 다운로드하거나 외부 서비스에 전송하지 않는다. 실제 Qwen 모델 ID·양자화·실행환경·VRAM은 미확인이다.

## 평가
각 사례에서 건강정보 요구 없음, 지어낸 회상 없음, 기록과 대사 일치, 자연스러운 캐릭터, 짧은 답변, 반복 방지, 상황 진행 여부를 사람이 확인한다. 건강정보 요구·허위 회상은 하나라도 발견되면 해당 버전은 채택하지 않는다. 생성 성공과 JSON 검증 통과는 대화 품질 합격을 뜻하지 않는다. 보고서는 work/evaluations에 저장하며 커밋하지 않는다. 평가는 가상 사례만 사용한다.

## 한계
knownBy와 sensitive는 신뢰할 수 있는 서버가 부여해야 한다. 현재 코드는 태그를 바탕으로 걸러내며 자연어에서 민감정보를 자동 식별하지 않는다. 사용자가 직접 입력한 건강 언급은 현재 요청에 들어가므로 별도 이력 저장을 하지 않는다. 프롬프트·텍스트·출력은 모듈이 자동 저장하지 않는다. 평가 스크립트는 가상 사례의 출력을 저장한다.

근거 ID가 존재하는지는 검사하지만, 모델이 그 ID와 상관없는 회상을 붙이거나 ID 없이 회상하는 것은 자동 차단하지 못한다. 사실 일치 여부와 건강정보 질문 여부는 현재 사람 평가 대상이다. 실제 모델 성능과 응답 지연, 다중 턴 지속 품질은 서버 연결 후 측정해야 한다. 자동 재시도·AI 기반 심판은 아직 추가하지 않는다. 원인과 실패 응답을 먼저 관찰한다.

## 모델 비교와 학습 순서
Qwen3 4B Instruct 2507 Q4_K_M, 설치된 Gemma3 4B Q4_K_M, Phi-4-mini를 첫 비교군으로 사용한다. Gemma4 E2B/E4B는 후속 후보다. 모든 실행은 로컬 Ollama /api/chat, context 4096, 출력 상한 350, temperature 0.4, seed 42로 통일한다. JSON 모드로 실행하므로 자유 출력 평가와는 조건이 다르다. 모델별 템플릿·토크나이저·출력 길이가 달라 속도 수치만으로 순위를 매기지 않는다. 이 실행은 단일 요청 예비평가이며 동시 접속 부하 시험은 아니다.

`node scripts/benchmark-ollama.mjs <설치된 태그> ...`는 각 사례의 원시 출력·구조 검증·시간·토큰·모델 사양을 중간 저장한다. 실패 출력도 분석용으로 보존한다. 설치된 모델만 사용하며 다운로드는 별도다. 실제 개인정보를 평가 사례에 넣지 않는다.

입력 10개 예비평가 뒤 서로 다른 NPC·기억 유무·잘못 전해진 소문·약속·장기 대화 사례를 늘린다. 후보 선정 후 수작업 검토한 학습 대화로 QLoRA를 시험한다. 평가 세트는 학습에 넣지 않고 인물·상황·표현도 분리한다. 사용자별 기억과 직업별 최신 정보는 외부 데이터에 유지하며 학습에는 기록 사용 행동과 말투를 넣는다. QLoRA는 모델의 불필요한 기능을 제거하거나 크기를 줄이는 작업이 아니다. 작은 모델로 행동을 옮기는 증류는 별도 후속 과제다.

공식 참고: [Qwen](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507), [Gemma3](https://ai.google.dev/gemma/docs/core/model_card_3), [Phi](https://huggingface.co/microsoft/Phi-4-mini-instruct), [QLoRA/PEFT](https://huggingface.co/docs/peft/main/developer_guides/quantization). 모델별 라이선스와 실제 배포 파일의 리비전을 기록한다.

`node scripts/summarize-benchmark.mjs <report.json> ...`로 결과를 집계한다. 형식 통과율과 사람 평가를 혼동하지 않는다. 워밍업 수치는 로딩 1초 미만 응답만 포함하며 작은 표본의 p95는 서비스 성능 보장이 아니다.

첫 실제 비교 결과: [2026-11-03 예비평가](model-baseline-2026-11-03.md).

현재 프롬프트는 npc-dialogue-v2다. 회상 기록이 없는 경우와 있는 경우를 별도 모드로 제공한다. 두 버전의 예비평가는 동일 사례를 사용했으므로 이후 독립 평가가 필요하다.
