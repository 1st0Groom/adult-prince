# 구조와 상태 규칙

## 개발 구조
- packages/simulation: 화면과 AI에 의존하지 않는 시간·상태·기억·약속 규칙
- data/occupations: 출처를 보존한 552개 직무 자료와 별도 시나리오 콘텐츠
- 향후 apps/web: PC 웹 화면과 1인칭 장면
- 향후 apps/api: 저장과 AI 호출, 상태 변경 요청 검증

첫 구현은 JavaScript 모듈로 상태 엔진을 만든다. 웹 화면은 기존 개발 경험을 활용할 수 있는 React·TypeScript·Three.js를 후보로 둔다. API 프레임워크와 저장소, 로컬 모델 실행 방식은 환경 확인 뒤 정한다.

## 처리 순서
플레이어 행동 → 상태·자원·시간 조건 검증 → 규칙으로 결과 반영 → 관찰 가능한 NPC에게 기억 기록 → 저장 → 관련 기억과 장면만 AI에 제공 → 응답을 검증해 대화 표시.

현재 엔진은 순수 함수로 새 상태를 반환한다. AI가 출력한 문장은 확정된 세계 사실과 분리한다. NPC 지식에는 직접 관찰·전해 들음 등 경로를 남긴다. 대화 프롬프트에는 전체 플레이 상태를 통째로 보내지 않는다.

## 구현된 범위
행동 시간·수면·약속·중요 사건 기억·반복 방문·NPC별 기억 조회·JSON 저장 형식. 저장 파일의 서버 검증, 관계 감쇠, 소문 전파, 일정 충돌, AI 연결은 후속 구현이다.
