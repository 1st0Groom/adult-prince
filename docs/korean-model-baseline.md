# Kanana·HyperCLOVA 예비평가 (2026-11-03)

RTX 3070 8GB, Ollama, 같은 가상 사례 10개. 원본 자체가 아니라 커뮤니티 Q4_K_M 변환본을 시험했다.

|---|---|---|
| Kanana 2.1B | 9/10 형식 통과 | 10/10 텍스트 생성, 허위 기억·주체 역전 발견 |
| HyperCLOVA 1.5B | 0/10 형식 통과 | 10/10 텍스트 생성, 허위 기억·주체 역전 발견 |

텍스트 생성은 품질 합격이 아니다. 일반 대화 진단은 --text-only로 짧은 자연어 지침과 실제 사용자 발화를 보내며, 구조화 평가와 입력 자체가 달라 차이를 JSON 요구 하나의 효과로 해석하면 안 된다.

## 관찰
Kanana 형식 평가에서는 기록 없는 과거를 모른다고 답하는 경우가 있었지만, 책을 주워준 기록에 “그게 처음이야. 그때부터 친해졌어”라는 관계 역사를 덧붙였다. 일반 대화에서는 여행 기억을 만들라는 입력에 바다·수영·음식을 지어냈고 책을 주워준 사람을 NPC로 바꿨다.

CLOVA는 요구 필드 대신 입력 요약 등 다른 JSON을 출력했다. 일반 대화에서는 첫 만남을 학교 앞 공원으로 지어냈고 책을 주워준 사람을 NPC로 바꿨다. 건강을 언급한 경우에는 쉬도록 배려하는 응답도 보였다.

## 실행 형식과 한계
Kanana 배포본의 Jinja 템플릿은 최초 구조화 실행에서 peg-native HTTP 500을 냈고 일반 대화에서 종료 토큰이 노출됐다. 원본 tokenizer_config의 역할 헤더를 확인해 config/models/kanana.Modelfile에서 도구 호출을 제외한 Llama3 계열 헤더와 종료 토큰을 명시했다. 표는 수정된 adult-prince-kanana:q4 결과다. 전체 원본 템플릿과 완전한 동등성을 검증한 것은 아니다.

CLOVA 원본 tokenizer_config는 로그인·접근 승인이 필요해 읽지 못했다. 공개 변환본에 Ollama가 적용한 ChatML 템플릿과 특수 토큰만 확인했다. 원본 접근 승인 후 공식 템플릿으로 재검증하기 전 모델 전체의 성능으로 일반화하지 않는다.

두 모델 모두 서비스 채택 보류. Kanana는 한국어 후보로 유지하고 독립 평가를 확대한다. 기억의 주체·대상·행동 구조화와 잘못 추가된 과거에 대한 검증이 필요하다. 실제 파인튜닝은 미실행이다.

## 사실 충돌 안내 유무 비교

2026-11-03. 5개 상황을 안내 없음/있음으로 짝지어 모델별 10개, 전체 40개 응답을 생성했다. 대사만 출력하며 같은 관계·기억·사용자 입력·seed와 생성 설정을 사용한다. 안내 있음에서는 NPC가 아는 구조화 기록과 구조화 주장의 비교 결과만 시스템 메시지에 추가했다.

### 구현 범위

packages/dialogue/claims.js는 같은 key의 구조화 value를 비교한다. NPC가 알거나 관찰한 기록만 사용하고 민감정보는 제외한다. 결과는 conflict / consistent / unknown / ambiguous다. 거짓말 의도나 실제 세계의 진실을 판정하지 않는다.

이번 테스트의 claim은 가상 사용자 문장에 대해 사람이 지정한 정답 구조다. 자유로운 한국어 입력에서 주장을 자동 추출하는 기능은 아직 없다. 따라서 이 시험은 올바른 충돌 안내를 줘도 모델이 반응을 표현할 수 있는지를 측정한다. 언어 이해·거짓말 자동 탐지의 종단간 성공률로 보고하지 않는다.

### 직접 관찰

- 약속 시간: Gemma는 안내가 없으면 동의했지만 안내가 있으면 오후 4시로 교정했다. CLOVA는 두 조건 모두 4시를 사용했다. Kanana는 두 조건 모두 틀린 3시에 동의했다. Qwen은 안내 없이 4시로 교정했으나 안내가 있으면 3시와 4시를 섞어 말했다.
- 책 주워준 주체 역전: 안내가 있어도 네 모델 모두 기록의 주체를 명확히 보존하는 교정에 실패하거나 모호하게 답했다.
- 처음 만난 사람의 과거 숙제 도움 주장: 안내가 있어도 여러 모델이 인정하거나 접촉 시점을 혼동했다. CLOVA는 기억이 없다고 반응했으나 누가 누구를 도왔는지 표현이 뒤집혔다.
- 맞는 주장 대조군: Kanana는 두 조건에서 감사하며 맞는 기록을 유지했다. CLOVA는 맞는 도움 주장에도 주체를 뒤집었다. Gemma는 안내가 있을 때 짧고 적절한 감사로 개선됐다.

### 구현한 기록 기반 응답 경로

말투/예의 반응 → 질문 의도 확인 → NPC가 아는 기록으로 답변 → 그 밖의 자유 대화 순서다. 모욕 속에 질문이 섞여도 먼저 NPC의 경계를 존중한다. 단순한 반말을 모욕으로 확정하지 않는다. 예의 행동 종류는 여전히 게임이 명시적으로 전달해야 하며, 자유 문장에서 무례함을 자동 판별하는 기능을 구현한 것은 아니다.

질문 의도는 확실한 한국어 표현을 좁은 규칙으로 먼저 처리하고 애매한 발언만 로컬 모델이 번호로 분류한다. 시간·장소·물건 보유자는 모델이 다시 써서 확정하는 대신 게임 기록으로 문장을 만든다. 자유 대화 전부를 정해진 대사로 바꾸지 않는다. 새로운 일정 제안·반납 요청은 조회와 구분해 일반 대화 경로로 보낸다. 그 요청의 실행이나 일정 변경은 이 경로가 수행하지 않는다.

대여 기록에는 빌려준 사람, 빌린 사람, 현재 가진 사람을 따로 둔다. 약속 기록에는 원래 합의, 현재 믿음과 출처, 현재 서로 합의한 일정을 구별한다. 여러 물건 중 무엇인지 모호하거나 NPC에게 보이지 않는 기록이면 첫 기록을 임의로 고르지 않는다. 현재 한 물건의 대여와 한 약속 조회를 지원하며 일반적인 모든 기억 검색은 미구현이다. 기록이 없는 경우 자유 대화에 위임하므로 그 구간의 허위 회상까지 자동 차단하지는 못한다.

## 카나나 대화 형식 점검

로컬 `adult-prince-kanana:q4`의 API 모델 정보에서 확인되는 템플릿은 저장소의 `config/models/kanana.Modelfile`에 적힌 간단한 템플릿과 다르다. API 표시값만으로 실제 렌더링에 어느 쪽이 적용됐는지 단정할 수 없다. 카카오의 [모델 카드](https://huggingface.co/kakaocorp/kanana-1.5-2.1b-instruct-2505)는 원본 토크나이저의 대화 템플릿 사용을 안내한다.

같은 모델·입력 3개를 기존 채팅 요청과 저장소 템플릿에 맞춘 직접 입력으로 각각 실행했다. 두 방식 모두 처음 만난 상대와 야구를 봤다고 잘못 동의했고, NPC가 가진 우산의 소지자를 혼동했다. 세 번째 평범한 인사에는 둘 다 대화가 이어졌다. 출력은 서로 달랐지만 이 작은 시험에서 직접 입력이 두 결함을 해결하지는 못했다. 따라서 템플릿 차이를 품질 저하의 원인으로 확정하거나 직접 입력을 기본값으로 채택하지 않는다.

큐웬의 [공식 토크나이저 설정](https://huggingface.co/Qwen/Qwen3-4B-Instruct-2507/raw/main/tokenizer_config.json)과 로컬 API에서 표시된 템플릿에는 차이가 있다. 실제 일반 대화에서 그 차이가 적용되는지와 품질에 영향을 미치는지는 별도 검증이 필요하다. CLOVA 변환본의 원본 템플릿 확인 제한도 계속 적용된다.
